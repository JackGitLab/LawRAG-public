## 1. 测量方法与指标定义

采集方式（三成，互不混淆）：

1. **客户端指标**：`tests/run_performance_baseline.py` 以真实 HTTP/SSE（`POST /api/chat/stream`）连接本次自建 uvicorn，`time.monotonic` 计时。`session` 事件不是回答首字。
2. **服务端分段与调用量**：不引入回调/追踪框架，在现有唯一 LLM 出入口 `app/observability.py::traced_invoke` 单点记录逻辑调用、耗时与供应商返回 usage；`app/graph.py` 给节点/工具计时；`app/ask.py` 给向量/BM25/重排计时（重排含实际尝试次数）。全部由 `LAWRAG_PERF_OBS_FILE` 门控，未设置时为空操作。
3. **隔离**：`LAWRAG_DB_PATH` 指向运行目录、Chroma 用运行目录内副本并改绑 `app.ask.CHROMA_DIR`、Langfuse 统一关闭并记录；采集前后保存真实目录逐文件 SHA-256 快照（实际证据，非布尔声明）。

指标定义与成功条件：

| 指标 | 定义 |
| --- | --- |
| 首段可见回答耗时 | 客户端开始发送请求 → 第一个非空回答文本事件（token） |
| 请求完成耗时 | 客户端开始发送请求 → 唯一 `done` |
| 失败耗时 | 请求开始 → 错误事件或连接异常 |
| 场景耗时 | 一次完整场景执行（多轮共一个任务）各轮请求耗时之和 |

- **成功条件（全部满足）**：无连接异常、无 error 事件、恰好 1 个 done、有非空回答且首段在 done 之前、done 后无非空文本。异常事件顺序（如 done→token）直接判失败，不只写备注；"done 之后"按原始事件**接收顺序**判断，同刻事件按保存顺序定先后（R2-04），时间戳只用于计时，不对时间线排序。
- **成功指标只属于满足成功条件的请求**；失败请求即使已收到 token 或 done，其时间只保留为原始观察值（observed_*），不进入成功统计。HTTP 200 不等于任务成功。
- **任务口径（R2-02/R2-03，R3 修订）**：一次完整场景执行 = 一个任务（两轮场景仍是一个任务）。**计划任务/计划请求来自 manifest 冻结计划**（场景、warmup_passes、formal_reps、必需轮次），未执行任务保留展示，不自动补跑；完整成功要求计划规定的每一轮**恰好一条**成功且路径匹配的记录（轮次身份与唯一性），重复轮次、缺轮、越界轮次的任务无效，不进完整场景耗时与费用分母（可核实费用仍计分子）；部分成功轮次不相加为完整场景耗时。
- **槽位统计口径（R3）**：计划/实际/异常三类分离。计划数字只来自冻结槽位（请求槽位身份 = scenario_id/phase/rep/turn_index，任务身份 = scenario_id/phase/rep），不按实际条数反推；未执行 = 空槽位数（不用计划数−实际条数，不用 max(...) 掩盖错配）。槽位恰好一条有效成功记录才计成功；无记录为未执行；同槽位多条为重复异常（不任选一条算成功）；计划外/重复/越界记录单列保留身份，不填补缺失槽位，不进计划内成功耗时与完整成功任务分母。实际请求总数与物理成功/失败单列可追溯。
- **原始 SSE 时间线（R1-06）**：新采集逐样本保存请求起点/结束（单调时钟相对偏移）、每个事件的顺序/类型/相对时间/是否非空可见文本、HTTP 状态、连接失败及时间；报告一律从原始时间线重算指标，不信任保存的派生 metrics。缺时间线的样本标 **NOT_VERIFIED**，不从旧 metrics 反向伪造时间线。
- 服务端分段与客户端时间分别统计，两台时钟不相减；node 层与调用层为包含关系，不跨层相加。
- **统计口径（R1-05）**：客户端成功耗时表只含成功请求；节点/调用/瓶颈表只用正式样本（含失败请求的服务端事实）；预热单列；调用与费用另给"含预热"的整次采集总账，预热＋正式可与总账对账。
- **费用（R1-03/R1-04，R2-01/R2-05 修订）**：只用该次运行 manifest 冻结的单价/币种/单位/模型映射/来源；**计费逐调用判断**（该次调用所需 usage 与费率完整才计费）再按模型汇总，同模型未知调用不抹掉已知费用，一次调用缺多个字段只计一个未知调用；usage 按字段判已知/未知，缺失不填零；缓存拆分缺失不假定零命中（只给针对该类未知调用的标注上界假设，不进已知合计）；缺单价或缺当前计价方式所需费率（含显式 None）产生含字段名的明确未知原因，不回退默认价、不静默记零、不抛 TypeError；显式数值 0 是有效费率；单模型价格不完整不影响其他模型可计费部分。费用合计只是**已知部分费用**，存在未知调用时不等于完整费用。
- **每成功任务费用** = 正式范围全部已知费用（含失败及计划外请求已发生的可核实费用）÷ **正式计划内完整成功任务数**（不是计划数；无效/未执行/计划外任务不进分母）；成功任务为 0 时 N/A；仅为已知费用部分，不等同实际扣费。
- 只发布 min/median/max；**不发布 P95（样本不足）**；不开展并发压测。

## 8. 缺参追问跳过检索

**图流程变化（明确记录，非所有节点顺序保持不变）：**

- 优化前：`prepare → retrieve → route → clarify / tools / generate → END`
- 优化后：`prepare → route →`（本轮路由判 clarify：`clarify → END`，跳过检索；否则 `retrieve → tools / generate → END`）

实现要点：route 前移，分支判断复用既有 `_next_node`（读取本轮 route 写入的 calc_context/planned_tool_calls）；每轮 route 只执行一次，不在 retrieve 后重调路由模型；跳过检索只由本轮路由结果决定，不按上一轮 awaiting 状态提前跳过；非 clarify 分支仍按 hybrid_rerank 配置检索一次；rewrite、router 调用次数、模型配置、工具协议与参数校验均不变；clarify 仍清空 citations/web_sources/tool_text，防上轮证据泄漏。
