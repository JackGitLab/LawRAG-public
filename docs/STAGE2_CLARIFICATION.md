## 1. 支持与不支持的行为

### 支持

1. 只有劳动补偿计算器的**明确计算请求**才进入追问流程：命中计算关键词（或已存在任务/明确取消/明确重试）时进入计算分支；未获得计算器工具调用即视为普通问答。
2. 逐字段核验来源后保存 `monthly_wage` / `years`（以及可选 `social_average_wage`、`kind`），只追问缺失项；两项都缺时一次说明两项；已知项不重复追问。
3. 等待补参时，`三年半`、`8000 元`、`工资改成 9000，工龄三年半` 这类简短回复可补齐一个或多个字段；**明确更正**以最新输入覆盖旧值；**明确无效更正**（零/负数）作废该字段。
4. 参数齐全后该轮只调用一次计算器；**实际执行成功**后才结束待补参状态（`status=done`）。
5. 计算完成后紧接着的明确更正更新参数但不重复计算；明确要求重算或重试时才重新调用。
6. 取消（`算了`、`不用了`、`不问了`、`取消`、`没事了`、`别算了`）或换话题时结束当前任务；后续新任务不继承旧参数。
7. 状态保存在现有 LangGraph SQLite Checkpointer；同一会话跨请求补参，不同会话互不影响；旧 checkpoint 缺少新字段仍可正常运行；不新增表或迁移；连接关闭与图重建后可恢复。
8. 追问同时出现在同步回答、SSE 页面与会话历史中；每轮只有一条助手消息；成功轮次只有一个 `done`。

### 不支持（明确边界）

1. 除劳动补偿外的金额问题（消费退款、商品价格、其他法律领域）不进入追问流程；模型若不调用计算器即按普通问答处理。
2. 不追问 `social_average_wage`，沿用现有可选语义（不提供即不启用三倍封顶）。
3. 不支持多个并行待办计算任务；同一会话始终只有一个 `calc_context`。
4. 不引入通用表单/工具注册框架、独立状态库、多 Agent、性能优化或权限系统；不改动 HTTP/MCP 公共接口与前端交互协议。
5. **追问轮不执行该轮已规划的其他工具**（`web_sources` 为空），也不会自动开启联网。
6. 不校验 `kind` 是否为法律上正确的解除类型；`kind` 由路由模型依情形判断，追问文案与计算器输出都显式写出“当前按 X 计算”的前提。
7. 追问轮的检索结果不展示（`citations` 置空），代价是该轮仍会执行一次检索。
8. **不支持复合年限**：“N年M个月”这类表达会被识别并阻断该轮年限（不接受 3、0.5、3.5 等任何片段），要求用户用统一年数确认；“三年半”“半年”等既有表达继续支持。
9. 不做通用中文数字解析：只支持阿拉伯数字与常用中文数词（含“半”）；小写/大写金额、日期式表达等无法确认时一律追问。

## 2. 状态字段及保存、覆盖、清除时机

新增状态字段：`ChatState.calc_context: dict | None`（`app/graph.py`），子字段：

| 子字段 | 含义 |
| --- | --- |
| `monthly_wage` / `years` | 已确认的必需参数；缺失或被本轮无效更正作废时为 `None` |
| `social_average_wage` | 可选参数，沿用现有语义，且只接受社平字段上下文给出的数值 |
| `kind` / `kind_explicit` | 计算类型及其“是否由模型明确给出”（决定是否写进工具调用参数） |
| `status` | `awaiting`（缺参待补）/ `computing`（本轮已规划、尚未执行）/ `done`（实际执行成功）/ `failed`（实际执行失败） |
| `reply` | 本轮回答方式：`ask`（缺参追问）/ `correction_ack`（更正确认）/ `None`（正常问答）；每轮由 `route` 重写 |
| `invalid_fields` | 本轮被明确作废的字段（零/负数更正），用于提示“需要大于 0 的有效数值” |
| `compound_years` | 本轮是否出现被阻断的复合年限表达，用于提示改用统一年数确认 |

时机表（`route` 每轮都会整轮重建 `calc_context`，无任务时写入 `None`，因此不会残留上一轮标记）：

| 时机 | 行为 |
| --- | --- |
| 每轮进入 `route` | 读取 `state.get("calc_context")`（旧 checkpoint 无该字段时为 `None`）；整轮重建并回写整个 dict |
| 本轮字段**未提供** | 保留同一任务已确认值，不采用模型额外生成的任何值 |
| 本轮**有效输入** | 该字段以本轮数值覆盖（仅在通过来源核验之后） |
| 本轮**明确无效更正**（零/负数且原话可证） | **在调用模型之前**从已确认字段移除该字段，并记入 `invalid_fields`；参数不齐即追问，绝不沿用旧值计算 |
| 本轮出现**复合年限** | 同样在调用模型之前移除已确认年限，`compound_years=true`，该轮不接受任何年限片段 |
| 显式新任务 | 从空参数开始（`base={}`），工资/年限/社平/类型/确认标记均不继承 |
| 参数齐全且本轮要计算 | `status=computing` 并规划恰好一次调用；完成后由 `call_tools` 写 `done`，异常写 `failed` |
| 计算完成后只更正、未要求重算 | 保留 `done`/`failed` 状态，`reply=correction_ack`，本轮不调用计算器 |
| 取消（无新的字段依据） | `calc_context=None` |
| 换话题（无字段线索、无数字、非取消/重试） | `calc_context=None` |
| 旧 checkpoint 无该字段 | 视为 `None`，当轮写入新值；不迁移、不加表 |

## 3. 参数来源规则

1. 参数只从用户本轮原话 `state["question"]` 抽取；被追问改写模型加工过的 `search_query` 不参与抽参。
2. `_scan_calc_literals()` 从原话里取数字字面量（阿拉伯数字或受限中文数词，支持“三年半/半年”与 `年/个月/元/万` 等单位）。**每个数值只归属一个组**，判定顺序如下：

| 数值上下文 | 归属 |
| --- | --- |
| 紧跟 `年`（后接“半”记 0.5）或 `个月` | 工作年限（时间单位优先，**不同时进入任何金额字段**） |
| 带 `元/块/万`，且其**所在片段**（以 `，,；;。.！!？?、换行` 为硬边界，只看当前片段）内出现 `赔偿 / 赔款 / 退款 / 退货 / 补偿金 / 违约金 / 罚款 / 金额` | 其他金额：**不作为任何工资依据** |
| 带 `元/块/万`，且当前片段内出现 `社平 / 职工月平均 / 职工平均工资 / 上年度职工` | 当地社平工资（该称谓常含“工资”，按完整字段含义优先于个人工资） |
| 带 `元/块/万`，且当前片段内出现 `工资 / 月薪 / 薪资 / 薪金` | 个人月工资 |
| 带 `元/块/万` 但当前片段内无字段线索 | 无法归属：只在字段含义唯一时可用（只剩一个待补工资字段，或原话只提到工资类字段） |
| 无金额单位，但当前片段前缀出现 `工资 / 月薪 / 薪资 / 薪金 / 社平` | 对应工资字段（同理，社平优先于个人工资） |
| 无金额单位，但前置出现 `工龄/年限/工作` | 工作年限 |
| 其余无单位数字 | 裸数字：仅在不含疑问标记且字段含义唯一时绑定 |

3. 字段词只看**当前片段**：已结束片段里的字段词不会抢占后面的数值（例如 `社平5000元，赔偿30000元` 中的 30000 归属于赔偿，不是社平；`社平5000元，月工资8000元` 中的 8000 归属于个人月工资）。无法确定归属时追问，不靠调整窗口长度掩盖冲突。
4. `2N` / `N+1` 里的数字被显式排除；带金额单位的数值不会进入裸数字池。
5. `_review_calc_args()` 逐字段核验模型返回：数值必须与上一步得到的该字段依据一致才会被处理——正数采用，零/负数记为无效更正；**没有依据的字段一律忽略**。
6. 复合年限（`N年M个月`）在核验前就把年限置为待确认，模型返回的任何片段值都不采用。
7. 无法确认字段归属或数值含义时继续追问，不猜测：裸数字与多字段歧义（例如“工资和工龄分别是 8000 和 4”）不绑定。

## 4. 缺参、补参、纠正、取消的调用路径

图结构（仅新增 `clarify` 节点与一条条件边）：

```text
prepare → retrieve → route → (clarify | tools → generate | generate) → END
```

处理顺序固定为：**明确取消 → 新任务重置 → 原话可证的无效更正与复合年限使旧值失效 → 核验模型新值 → 补齐/执行/保留待办**。

1. **缺参**：核验后必需字段仍缺 → `status=awaiting`、`reply=ask` → `clarify` 输出确定性文案并置 `citations=[]`，不经过生成模型。
2. **补参**：`awaiting` 下补齐 → `status=computing` 且规划一次调用 → `tools` 执行成功 → `call_tools` 写 `status=done` → `generate` 生成回答。
3. **无效更正**：无论模型是否报出该字段，原话可证的零/负数更正直接作废该字段并追问，不计算。
4. **纠正（计算完成后）**：参数齐全但本轮未表达计算请求 → 保持原状态、`reply=correction_ack`，不重复调用。
5. **取消**：`_is_calc_cancel(原话)` 且本轮没有新的工资/年限依据 → 直接结束任务，**不调用路由模型**。
6. **相关澄清**：`awaiting` 且本轮没有可采用的新字段值、但本轮在问当前缺失字段（如“月平均工资是税前还是税后？”）→ 保留任务、`reply=None`，按普通检索问答回答；模型返回空调用、仅 `kind` 或无依据的旧参数都不改变该分流。
7. **无法归属的金额或数值**：保留任务、`reply=ask`，并说明需要什么样的数值。
8. **换话题**：`awaiting` 但本轮没有字段线索、没有金额/数字、也不是取消/重试 → `calc_context=None`。
9. **执行失败与重试**：计算器抛错 → `status=failed`，失败说明进入生成上下文，不宣称成功、不自动重试；明确“重试/重新计算”时沿用仍有效的已确认参数再执行一次，成功后才写 `done`。
10. **SSE**：`stream_turn` 在 `generate` 无 chunk 且快照 `answer` 非空时补发整条文本；参数收集过程的模型输出被既有节点过滤规则挡住。

## 9. 已知限制与未验证事项

1. **真实模型覆盖面**：R2、R3 均未修改提示词、未新增真实调用。C2-03/05/06/11/12 的真实行为仍 **NOT_VERIFIED**；C2-02/04/09/10 修复后未逐项复跑；R2 新增边界（其他金额、字段错配、复合年限、无效更正的漏报路径）与 R3 新增边界（片段边界、时间单位优先、字段排列）在真实模型下的表现同样 **NOT_VERIFIED**。
2. **其他金额的判定依赖字段词表**：`赔偿/赔款/退款/退货/补偿金/违约金/罚款/金额` 之外的表述（如“老板答应给我三万”）不构成“其他金额”，可能被当作无法归属金额；反之若工资描述里出现上述词也可能被排除。字段词只在**同一片段内**生效，因此在“工资就是那笔赔偿金，8000 元”这类同片段混写中，8000 仍会被判为“其他金额”而不可用（退化为追问，不会误算）。
3. **社平工资依据范围较窄**：只认 `社平/职工月平均/职工平均工资/上年度职工` 的当前片段上下文，其他写法（如“当地平均工资”）会被当成个人月工资依据。字段先后顺序不再影响归属，但词表外的社平称谓仍无法识别。
4. **复合年限一律阻断**：包含日期式表达（如“2023年6月入职”）也会被识别为复合表达而要求确认，代价是多一次追问。
5. **中文数词为受限实现**：小写/大写金额、繁体或复杂组合不被识别，一律追问而非猜测。
6. **`kind` 仍由模型判断**（见 §1 第 6 条），不新增法律适用条件校验。
7. **澄清轮与取消轮的回答来自生成模型**：只保证“不重复索要参数、如实回答”；语料未覆盖时实测得到“现有资料无法回答。”。
8. **判定依赖固定词表**：取消、重试、新任务、字段词、其他金额词都是固定列表，词表外表达退化为追问或普通问答（不会误算）。
9. **`E-038` 的非确定性依然存在**：同一提示词重复调用仍可能出现空调用或参数形态差异。
10. **追问轮仍会执行一次检索**并随后丢弃；**追问轮不执行本轮其他已规划工具**；不支持同一会话内多个并行计算任务；未做多进程/多实例并发写入验证。
