# 精选工程复盘

三个案例来自项目真实开发与独立验收记录，展示问题、修复与防回归方法。它们是历史工作的摘要，本次文档整理没有重新执行这些独立验收，也不据此宣称真实模型全面通过。

## 1. 答案变了，旧评分却仍然有效

**问题。** 记录中的 `result_hash` 被直接当作可信身份；答案修改后保留旧哈希，旧评分仍可能被接受。待法律复核的标注还可能进入正式统计。

**处理。** 从实际内容重算身份，核对保存身份、评分绑定与冻结题集；有失配时拒绝复用评分。将待审标注与已审统计分流，固定计划分母。

**验证。** 回归覆盖修改答案但保留旧哈希、题集身份变化、缺失身份和待标注引用。不是只检查正常输入下分数是否合理。

**取舍。** 保留需要人工复核的状态，不自动刷新旧哈希掩盖失配，也不用执行者初评代替独立法律判断。

入口：[实现](../tests/run_quality_evaluation.py) · [测试](../tests/test_quality_evaluation.py) · 历史验收（未公开的历史记录）

## 2. 新任务继承了上一次的工资与年限

**问题。** 在同一会话里切换计算对象时，旧参数可能残留；用户将工资改为无效值后，也可能继续使用旧工资。仅凭模型抽取结果不能证明参数来自本轮用户。

**处理。** 在合并参数和执行工具前检查字段来源，并明确补参、更正、新任务与取消的状态转换。单位与字段归属共同约束数值，工具执行失败保留失败状态。

**验证。** 覆盖新任务隔离、无效更正、取消、工资与社平工资混淆、年限混入金额，以及 checkpoint 恢复路径。

**取舍。** 对不明确的输入追问；保留单会话单待办计算任务的边界，不为模糊输入静默猜测。

入口：[图实现](../app/graph.py) · [测试](../tests/test_calculation_clarification.py) · 历史验收（未公开的历史记录）

## 3. 清理命令执行过，不等于资源已释放

**问题。** 连接超时被误判为端口释放，进程查询失败被视为进程不存在；终止命令失败仍可能记为已清理。错误输出为 bytes 时，还会影响 manifest 保存。

**处理。** 区分已释放、仍存在和未知；检查命令返回码与后续状态，将错误输出转换成可落盘文本。每次探测和等待考虑剩余预算，整体清理成功要求父进程、后代及端口状态均已确认。

**验证。** 覆盖真实监听队列满、诊断失败、非零返回码、实际 bytes 错误输出贯穿 manifest，以及剩余 10ms 的等待边界。

**取舍。** 未知不写成功，首次异常不被后续成功检查覆盖。清理仅限本次拥有的资源。

入口：[测量工具](../tests/run_performance_baseline.py) · [测试](../tests/test_performance_baseline.py) · 历史验收（未公开的历史记录）

## 本地完整档案

完整错误记录继续位于本地 `docs/ERRORS.md`，不进入当前 Git 文件树；全量日志位于 `logs/`。全新克隆没有这两类私人过程材料，不影响正式离线回归。完整历史错误记录未公开，本文仅提供精选案例摘要。

本地档案检查不再读取 Git HEAD。开始修改前，复制一份快照到 `logs/`，然后显式比较：

```powershell
Copy-Item -LiteralPath docs/ERRORS.md -Destination logs/errors-before-task.md
.\.venv\Scripts\python.exe scripts/check_error_archive.py --show E-102
.\.venv\Scripts\python.exe scripts/check_error_archive.py --expect-changed E-102 --baseline logs/errors-before-task.md
```

每次任务使用新的快照文件名；不要覆盖上一任务的快照。没有本地档案时，应先创建记录或从自己的备份恢复；检查工具会明确报告缺失，不把缺失当作检查通过。
